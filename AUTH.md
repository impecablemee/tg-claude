# Как каждый человек подключает свой Telegram

Один раз на человека. Делается ПРИ НЁМ — это его аккаунт, а не ваш.

---

## Что именно происходит

Человек сканирует QR-код своим Telegram — так же, как подключают Telegram Desktop.
На сервере появляется файл `sessions/<имя>.string`. **Этот файл — и есть его
Telegram.** Относиться к нему как к паролю:

- лежит на вашем сервере, в вашем каталоге, права `0600`;
- в git не попадает никогда (`.gitignore` закрывает `sessions/`);
- отзывается в одно касание: Telegram → Настройки → Устройства → завершить сеанс.

Скажите эту последнюю фразу каждому вслух при подключении. Согласие, которое
нельзя отозвать одним касанием, — не согласие.

---

## Шаг 1. Человек готовит папку в Telegram

**До** сканирования, а не после. Иначе первый же синк прочитает не то.

1. Telegram → Настройки → Папки → Создать папку.
2. Название — одинаковое у всех, например `Work`.
3. Положить в неё **только те чаты, которые он согласен показать**: клиентские
   диалоги, рабочие группы. Личное туда не класть.

Папка — это граница, и она живая: вытащил чат из папки — со следующего прогона
его перестают читать. Список папки перечитывается каждый прогон, а не
запоминается один раз.

## Шаг 2. Запуск авторизации

На сервере, вместе с человеком:

```bash
cd ~/tg-claude
connector/.venv/bin/python connector/tg_login.py --slug anna --folder Work
```

- `--slug` — короткое имя латиницей, им же человек будет называться в отчётах;
- `--folder` — ровно то название папки, которое он создал на шаге 1.
  Если человек предпочитает не разделять чаты папкой, есть `--folder '*'`:
  читается весь аккаунт, включая личные чаты. Это осознанный выбор владельца
  аккаунта, и сказать ему об этом надо прямо — папка существует именно затем,
  чтобы такого не происходило по умолчанию.

В терминале появится QR-код (и файл `qr.png`, если удобнее показать картинкой).

## Шаг 3. Человек сканирует

Telegram на телефоне → **Настройки → Устройства → Подключить устройство** →
навести камеру на QR.

Если у него включён облачный пароль (2FA) — скрипт спросит его прямо здесь.
**Пароль вводит сам человек, он нигде не сохраняется.**

## Шаг 4. Проверка, что всё село

```bash
connector/.venv/bin/python connector/tg_sync.py --slug anna --limit 20
```

Должно напечатать что-то вроде `anna: 12 chats in scope, 240 new messages`.

- `0 chats in scope` — папка называется не так, как указано в `--folder`, или в
  ней пусто;
- `session revoked` — человек завершил сеанс в Устройствах, нужно подключить заново.

## Частые вопросы, которые задают при подключении

**«Вы прочитаете мою личную переписку?»**
Читается только то, что он сам положил в папку. Не положил — не прочитаем. Это
не обещание на словах: `tg_sync.py` каждый прогон берёт состав папки у Telegram
и работает строго по нему.

**«Вы сможете писать от моего имени?»**
Нет, и это проверяется двумя способами. Барьер в рантайме отбивает любой пишущий
вызов до сокета; статический страж роняет сборку, если пишущий метод хотя бы
упомянут в коде. Запустите при нём `python3 connector/guard_readonly.py` — он
напечатает, сколько попыток записи заблокировано на самопроверке.

**«Что будет, если я передумаю?»**
Telegram → Устройства → завершить сеанс. Чтение прекращается немедленно. Что уже
прочитано — остаётся в базе на вашем сервере; удаляется командой
`--forget-out-of-scope`, если попросит.

## Порядок для команды из нескольких человек

Подключать по одному, с интервалом. Первый синк каждого аккаунта — самый тяжёлый
запрос к Telegram; если запустить пятерых одновременно, упрётесь в лимиты и
будете ждать вместо работы. Синк и так ходит по аккаунтам последовательно, а не
параллельно, — это осознанное решение, см. шапку `connector/tg_sync.py`.

Один аккаунт — один процесс, всегда. Два процесса на одном ключе авторизации
Telegram видит как вход с двух адресов и **отзывает ключ** — не притормаживает,
а отзывает, и человеку придётся сканировать QR заново.
