# Только ноутбук: без сервера

Один человек, своя машина, никакой инфраструктуры. Смысл — выяснить за один
вечер, полезны ли ответы по вашей переписке, до того как разворачивать что-либо
на сервер.

Работает на macOS и Linux. На Windows — через WSL.

---

## Что понадобится

- Python 3.10+ (`python3 --version`)
- Claude Code (`claude --version`) — если нет: `curl -fsSL https://claude.ai/install.sh | bash`
- Telegram на телефоне

## 1. Код и зависимости

```bash
git clone <адрес-этого-репозитория> ~/tg-claude && cd ~/tg-claude
python3 -m venv connector/.venv
connector/.venv/bin/pip install -r connector/requirements.txt

connector/.venv/bin/python connector/guard_readonly.py     # должно напечатать OK
```

Последняя строка — не формальность. Это доказательство **на вашей машине**, что
код не умеет отправлять, полученное до подключения аккаунта, а не после.

## 2. База

```bash
mkdir -p connector/data
connector/.venv/bin/python -c "import sqlite3; sqlite3.connect('connector/data/tg.db').executescript(open('connector/schema.sql').read())"
```

Питоном, а не утилитой `sqlite3`: питон уже есть, а отдельной утилиты на машине
может не быть — на Linux она ставится отдельным пакетом.

## 3. Папка в Telegram

**До** подключения, а не после — иначе первый синк прочитает не то.

Telegram → Настройки → Папки → Создать папку → назвать `Work` → положить туда
**только те чаты, которые готовы показать**. Личное не класть.

Папка живая: вытащили чат — со следующего прогона его перестают читать.

## 4. Подключить свой аккаунт

```bash
connector/.venv/bin/python connector/tg_login.py --slug anna --folder Work
```

Появится QR-код. Telegram на телефоне → Настройки → **Устройства → Подключить
устройство** → навести камеру. Если стоит облачный пароль — скрипт спросит, вы
вводите сами, он нигде не сохраняется.

Отозвать в любой момент: Устройства → завершить сеанс.

## 5. Первый синк

```bash
connector/.venv/bin/python connector/tg_sync.py --slug anna --limit 200
```

Ожидаемое: `anna: 12 chats in scope, 240 new messages`.

- `0 chats in scope` — папка называется иначе, чем указано в `--folder`, или пуста
- попросили подождать (`flood_wait`) — нормально на первом синке большой папки:
  прочитанное сохранено, следующий запуск продолжит с места остановки

## 6. Спросить

```bash
cd ~/tg-claude && claude
```

Запускать **из каталога репозитория** — оттуда читается `.mcp.json`, и только
поэтому Claude видит вашу переписку. Из другого места он ответит вежливо и
совершенно мимо.

Вопросы, на которых сразу видно, работает ли это для вас:

```
какие telegram-аккаунты подключены и за какой период есть данные
что нового у <клиент> за последнюю неделю
кому мы не ответили дольше двух дней
что мы кому обещали и когда — по всем чатам за месяц
```

Первым делом спрашивайте **про покрытие**: «за какой период есть данные». Цифра,
посчитанная по наполовину синхронизированной базе, — это неверный ответ, который
выглядит правильным.

## Обновлять данные

Вручную, когда нужно:

```bash
cd ~/tg-claude && connector/.venv/bin/python connector/tg_sync.py
```

Автоматически, пока ноутбук не спит (macOS — `launchd`, Linux — `cron`). А если
нужно, чтобы данные были свежими всегда, — это уже сервер:
[LOCAL_CLAUDE.md](LOCAL_CLAUDE.md).

## Чего здесь нет

| | |
|---|---|
| Свежесть данных | пока машина включена и не спит |
| Общая база на команду | нет, у каждого своя |
| Коллеги видят ваши ответы | нет |

Это ровно то, ради чего дальше берут сервер. Но проверять пользу удобнее здесь:
разворачивать нечего, а если не зашло — просто удалить каталог.

## Как удалить всё

```bash
rm -rf ~/tg-claude
```

И у себя в Telegram: Настройки → Устройства → завершить сеанс. После этого ни
одного следа не остаётся ни на какой стороне.
