# Telegram → Claude, только чтение

Claude читает переписки вашей команды в Telegram и отвечает на вопросы по ним.
Ничего никому не отправляет — это запрещено кодом, а не обещанием.

---

## Как это устроено

Две ваши машины и внешний Telegram, к которому ходит только сервер:

```
  ВАШ КОМПЬЮТЕР              ВАШ СЕРВЕР                  TELEGRAM
  ─────────────              ──────────                  ────────
  Claude Code  ─── ssh ──▶   база переписки  ◀── синк ── чаты из вашей папки
  (ваш доступ)                                           (по вашей сессии)
```

Сервер делает одну работу: складывает в базу те чаты, которые человек сам положил
в оговорённую папку Telegram. Telegram присылает новое сам, в открытое
соединение, — сообщение попадает в базу за секунды, опроса нет. Наружу сервер
ходит только к Telegram и только за чтением; данные из базы не уходят никуда.

Claude работает у вас на компьютере и читает эту базу через ssh — на сервер его
ставить не нужно.

Читает **пользовательская сессия** — тот же протокол, которым работает Telegram
Desktop. Каждый человек один раз сканирует QR-код, при нём. → [AUTH.md](AUTH.md)

## С чего начать

**→ [START.md](START.md)** — какой вариант брать.

Коротко: **сервер нужен не всегда.** Проверить, полезны ли ответы по вашей
переписке, можно на обычном ноутбуке, вообще ничего не разворачивая
([LAPTOP.md](LAPTOP.md)). Сервер берут потом — под уже доказанную пользу.

| | Свежесть данных | Общая база на команду |
|---|---|---|
| [Только ноутбук](LAPTOP.md) | пока ноутбук открыт | нет |
| [Сервер + Claude на ноутбуке](LOCAL_CLAUDE.md) | всегда | да |

Общее для обоих: каждый сам решает, какие чаты показать (правило 1 ниже).

После этого вопросы вида «что мы обещали Coastline Gaming в июле и кто за это
отвечает» имеют ответ, потому что ответ — это файл, а не чья-то память.

## Что внутри

| Каталог | Что это |
|---|---|
| `connector/` | чтение Telegram → SQLite → инструменты для Claude. **Отправлять не умеет физически** |
| `brain/` | обычный markdown: файл на аккаунт, на человека, на решение. То, что накапливается |
| `ops/` | ежедневная эксплуатация и как система сама находит повторяющиеся вопросы |

## Четыре правила, на которых всё держится

1. **Папка — граница, и она двигается за минуту.** Читаются только чаты, которые
   человек сам положил в оговорённую папку Telegram. Состав папки перечитывается
   раз в минуту, а не кэшируется: вынесли чат — читать перестают в течение
   минуты, внесли — читают с той же минуты, ждать сверки не нужно.
   `connector/tg_live.py`; проверка — `connector/test_live_rescan.py`.

   Область **настраивается владельцем аккаунта**: `--folder Work` — только эта
   папка (по умолчанию), `--folder '*'` — весь аккаунт целиком, границы нет.
   Второй режим существует, потому что кому-то удобнее держать рабочее в папке,
   а кому-то нет; выбирает человек про СВОЙ аккаунт и вслух, а не код молча.
2. **Только чтение — проверяется дважды.** Барьер в рантайме отбивает любую
   запись до того, как она уйдёт в сокет (`connector/readonly.py`), а статический
   страж роняет сборку, если хоть один файл упоминает пишущий метод
   (`connector/guard_readonly.py`). Барьер устроен как список РАЗРЕШЁННОГО:
   проходит только чтение, всё незнакомое отклоняется — запрещающий список
   закрывает лишь то, о чём вспомнили. Проверить самим:
   ```bash
   python3 connector/guard_readonly.py     # должно напечатать OK
   python3 connector/test_barrier_holes.py # отправка, реакции, вступление в чаты,
                                           # звонки, выход из аккаунта — отклонены
   ```
3. **Голосовые читаются наравне с текстом.** Голосовое расшифровывается и
   лежит рядом с сообщением, поэтому «иди разберись в чате, там голосовуха»
   работает. Если расшифровка на этом аккаунте недоступна, инструмент говорит
   это словами: «содержание НЕИЗВЕСТНО», а не отдаёт пустое поле — пустое поле
   читается как «ничего не сказали».
4. **Пробел никогда не выдаётся за пустоту.** «У Acme нет сообщений» и «Acme ни
   разу не синхронизировали» — разные ответы, и действовать можно только по
   одному из них.

## Как отозвать доступ

Одно нажатие, у каждого своё: Telegram → Настройки → Устройства → завершить
сеанс. Согласие, которое нельзя отозвать в одно касание, — не согласие.
